# R1 capture authorization

MotionPaste accepts a capture only for a user-started picker session, bound to the Chrome tab and document that received the picker. The release keeps only `activeTab`, `scripting`, and `storage`; it adds no host permission or externally connectable endpoint.

## Reproduced defect

Before the change, an own-extension HTTP(S) top-frame content script could send `MOTIONPASTE_CAPTURE` without starting a picker. The added regression `worker rejects a capture without an authorized picker session` failed with `true !== false`, and the worker stored the recipe and opened Studio. This was reproduced before editing the worker. The original four worker tests accepted that behavior and did not establish user authorization.

## Message contract

| Message                                              | Allowed sender                                                                                                          | Behavior                                                                                                                                                                                                                      |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MOTIONPASTE_BEGIN_CAPTURE` with `tabId`, `windowId` | Exact own `popup.html` extension URL and extension ID                                                                   | Use the tab selected by the popup in its own window, verify the tab/window and HTTP(S), ask Chrome for its current top-frame document ID, persist a new random token and deadline, then inject the picker into that document. |
| `MOTIONPASTE_CAPTURE` with `token`, `recipe`         | Own top-frame content script, active document, matching browser-provided tab and document IDs, matching unexpired token | Consume the token, recheck the tab's current document, validate the recipe, commit the capture, then open Studio.                                                                                                             |
| `MOTIONPASTE_CANCEL_CAPTURE` with `token`            | Own top-frame content script matching that session's tab, document, and token                                           | Remove only that session. Also allowed when the document has become inactive during `pagehide`; stale cancellation cannot remove a newer token.                                                                               |
| `MOTIONPASTE_GET_CAPTURE` with `id`                  | Exact own Studio origin and pathname                                                                                    | Return a validated, unexpired stored recipe. Existing capture link restrictions remain.                                                                                                                                       |

Tokens are generated with `crypto.randomUUID()`, last five minutes, and are single-use. A matched capture attempt consumes the token even when recipe validation or later injection checks fail. The picker tells the user to start a new capture after a submitted request fails; local unsupported-animation errors still allow choosing another element.

The worker persists bounded sessions in `chrome.storage.session` as `{ tabId, documentId, token, expiresAt }`, at most 20 unexpired sessions and one per tab. It stores no source URL, title, HTML, or page content. The existing capture history remains bounded to ten records, 512 KiB, and 30 minutes. Session storage is restricted to trusted extension contexts.

The popup resolves its selected tab and window before sending BEGIN. The worker uses `tabs.get(tabId)` and checks that window identity; it never reselects an active tab from the worker context. This prevents a focus change while messaging from switching authorization to another tab.

All message transactions use a serial queue. Registration completes before picker execution. The token is passed by `chrome.scripting.executeScript` arguments into the extension's isolated world, read by the picker, and immediately removed from the shared isolated global. There is no page-world message hook or DOM token attribute. Both token setup and picker injection target Chrome's `documentId`, so intervening navigation fails closed. Injection failure clears the pending session. A repeated invocation replaces its prior token before the old picker cleanup can run.

The worker checks the currently active top-frame document again when accepting a capture. Matching an old saved document ID is insufficient after navigation. Studio opens only after the capture write resolves, preventing its initial data request from racing the store.

Chrome documents these identities and execution boundaries in the official [scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting) (`InjectionResult.documentId`, `InjectionTarget.documentIds`, isolated execution world) and [runtime API](https://developer.chrome.com/docs/extensions/reference/api/runtime) (`MessageSender.documentId`, `frameId`, and `documentLifecycle`). Document targeting is available from Chrome 106; the release's minimum Chrome version is stricter.

## Verification boundaries

`tests/worker.test.ts` exercises the bundled worker listener with mocked Chrome APIs. Its 16 cases cover absent authorization, popup identity, protected pages, wrong token/tab/document/frame/extension/lifecycle, worker recreation with retained session storage, concurrent replay, expiry, navigation, revoked access, registration before early capture, immediate Studio reads, replacement and late cancellation, pagehide cleanup, injection failures, malformed payloads, record count, and storage bytes. These tests do not simulate actual Chrome permissions or worker suspension.

`scripts/authorization-test.mjs` extracts the versioned release ZIP into a fresh Chromium profile, checks member hashes and permissions, and invokes the real toolbar action. Failure requests originate from actual isolated content scripts; their sender identities are generated by Chrome, not forged test event objects. The report includes the archive SHA-256, manifest version, browser version, each executed check, and limitations. It covers rejection before BEGIN, successful actual picker capture, token replay, cross-tab use, document navigation, stale cleanup, expiry, and Escape cancellation. The expiry case explicitly changes the timestamp from a trusted test context rather than waiting five minutes. This authorization suite does not stop the worker. beta.3 adds a separate [actual forced worker stop/restart suite](WORKER_LIFECYCLE.md), with observed Chrome termination and recreated globals. The retained-storage VM recreation case remains a unit test; natural idle termination and a whole-browser restart remain untested.

During actual-browser verification, the existing toolbar helper intermittently clicked the popup button before its script registered the handler. A failing run showed an idle popup, empty status, enabled Capture button, and no capture session. The helper now waits for popup document readiness before clicking and for popup closure after picker initialization. Eight consecutive actual open/Escape cycles passed after that helper correction. Multi-tab verification then exposed a separate product focus race: the worker reselected its context-current tab, and the popup reported a protected-page error even though the intended source was HTTP(S). BEGIN now carries the popup-selected tab/window, and the worker verifies and uses that exact target. The helper retains the real toolbar `activeTab` grant and the real popup button path.

The current machine-readable result is `artifacts/verification/authorization-report.json`. Its status and archive hash are authoritative; this document does not turn unexecuted checks into a pass or claim browser coverage beyond the recorded local Chromium run.
